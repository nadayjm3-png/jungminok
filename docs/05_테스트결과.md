### 6.1 자동 검사

기존 54개에 operations.test.ts 22개, recovery.test.ts 8개를 추가해 **84개 통과**, TypeScript 검사와 Vite 프로덕션 빌드 통과를 확인했다. 이후 최종 변경은 다시 검사한다.

- 기간 6종과 윤년·연도 경계, 마감/미마감/휴무·부분 자료, 실제 비용만 차감, 비용 중복·빈칸·음수·0·항목·날짜를 검사했다.
- 입고·폐기·실사 0, 같은날 실측 중복, 실측 이전 수정, 음수 잔량, 단위·수량·공급사·날짜 오류를 검사했다.
- 독립 예시로 월말 예상 1,440,000원 매출·369,000원 직접비·80,000원 공통비·991,000원 손익을 대조했다. 실제 비용 변경이 월계획을 자동 바꾸지 않음을 검사했다.
- 우유 평균 2,000ml, 목표 4,000ml, 잔량 2,999ml이면 부족 1,001ml→2묶음→2,000ml를 검사했다. 평균에 폐기를 섞지 않음, 사용 0·표본 부족·구매용량 오류도 검사했다.
- 전체 백업 왕복·과거 원가·실측량·설정 보존, 비용/재고 재접속, 지원 밖 형식·정책·중복·누락 거부, 복원 실패 시 모든 표와 revision 전체 취소를 검사했다.
- 첫 복원 시나리오 검사 4건은 기본 5초 제한을 초과했다. 실제 데이터 규모의 전체 복원/재접속 시나리오만 20초 제한으로 재실행해 통과했다. 계산값 오류를 숨기거나 검사 항목을 삭제하지 않았다. 이 조정은 사용자 체감 속도 목표 달성을 의미하지 않는다.
