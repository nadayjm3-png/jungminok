## 1. 전체 작업 순서와 나눈 이유

EPIC은 함께 완성할 작업 묶음이고, User Story는 사용자가 한 가지 목적을 달성하는 기능 단위다.

1차 개발은 **EPIC 3개, Story 14개**다. EPIC별 Story는 5개·5개·4개로, 각 상한과 전체 15개 미만 조건을 만족한다.

| 순서 | EPIC | Story 수 | 끝나면 화면에서 확인할 결과 |
|---|---|---:|---|
| 1 | 판매 기록과 메뉴·재료 연결 | 5개 | 판매를 입력하거나 가져오고, 메뉴 수익성과 재료 잔량을 확인 |
| 2 | 비용과 재고를 반영한 매장 실적 | 5개 | 비용·입고·폐기·실제 재고를 기록하고 기간 손익 확인 |
| 3 | 전망·발주 참고와 자료 복구 | 4개 | 월말 예상 손익·부족 재료·참고 발주량 확인, 백업·복원 |

판매 자료가 있어야 수익성과 재료 사용을 계산할 수 있고, 비용·재고가 정확해야 전망과 발주 참고량을 믿을 수 있다. 이 의존성에 맞춰 순서를 정했다.

엑셀 양식 다운로드는 '판매 기록을 한꺼번에 가져오기'의 준비 단계로 묶었다. 반면 입고·폐기·실사와 백업·복원은 사용자 목적이 달라 각각 나눴다. 판매와 비용의 추가·수정·삭제는 각각 같은 종류의 기록을 정확하게 관리하는 목적 안에 둔다.

현재 FRD에는 미정 계산·동작이 남아 있다. 관련 Story는 **해당 기준을 확정한 후 구현·검증해야 완료**다. 이번 계획 확인이 미정 계산 기준의 승인까지 의미하지는 않는다.

## 2. EPIC 1 — 판매 기록과 메뉴·재료 연결

**포함 Story: US-01~US-05, 총 5개**

### US-01. 매장 기본 자료를 확인한다

- **사용자가 할 수 있는 일:** 제공된 샘플의 메뉴·재료·레시피·공급사·가격 이력을 조회한다.
- **자동 검사:** 샘플 최초 저장과 재접속 시 중복 삽입 방지, ID 연결·단위 검사, 저장 실패 시 기존 자료 보존.
- **화면에서 확인할 행동:** 프로그램을 열어 메뉴와 레시피를 확인하고 다시 접속한다.
- **예상 결과:** 실제 자료의 메뉴 8개·재료 11개·공급사 3개가 보이며 재접속해도 개수가 늘어나지 않는다. 시안의 다른 메뉴·가격을 사용하지 않는다.

### US-02. 직접 입력한 판매 기록을 관리한다

- **사용자가 할 수 있는 일:** 날짜·메뉴·채널별 판매 기록을 추가하고, 잘못 입력한 기록을 수정·삭제한다.
- **자동 검사:** 승인된 판매금액·원가·수수료 계산, 입력 누락·중복 클릭·저장 실패, 수정·삭제 시 이전 영향 제거, 재접속 후 보존.
- **화면에서 확인할 행동:** 판매 한 행을 저장하고 수량을 수정한 뒤 삭제한다. 잘못된 입력으로도 저장을 시도한다.
- **예상 결과:** 목록과 금액이 변경에 맞게 바뀌고, 삭제하면 해당 기록이 사라진다. 오류 입력은 이유가 표시되며 기존 기록은 유지된다. US-04·05 완성 후 수익성과 잔량까지 연결 확인한다.

### US-03. 판매 기록을 엑셀로 한꺼번에 가져온다

- **사용자가 할 수 있는 일:** 정해진 양식을 내려받아 작성하고, 검사 결과를 확인한 뒤 판매 기록을 등록한다.
- **자동 검사:** 내려받은 양식의 재읽기, 필수 열·날짜·메뉴ID 검사, 파일 내부/기존 기록 중복, 승인된 오류 처리 정책, 등록 실패 시 부분 저장 방지.
- **화면에서 확인할 행동:** 정상 파일과 오류·중복이 있는 파일을 각각 선택한다. 검사 후 등록을 실행하고 다시 접속한다.
- **예상 결과:** 검사만 할 때는 판매와 재고가 바뀌지 않는다. 오류에는 행 번호와 이유가 나온다. 등록한 기록은 목록에 남고, 같은 파일 재등록은 승인된 중복 정책대로 처리된다.

### US-04. 메뉴별로 남는 금액을 확인한다

- **사용자가 할 수 있는 일:** 선택 기간의 메뉴별 판매량·매출·직접 비용·수익성을 비교한다.
- **자동 검사:** 판매 당시 원가 보존, 채널별 포장비, 개당 금액·비율, 분모 0·누락 원가 처리. 별도로 계산한 기대값과 대조한다.
- **화면에서 확인할 행동:** 같은 메뉴를 매장·포장으로 판매한 뒤 수익성 표를 확인하고 판매수량을 수정한다.
- **예상 결과:** 채널에 맞는 비용과 수정된 판매가 반영된다. 임차료·인건비는 메뉴에 배분하지 않는다. 계산 자료가 없으면 정상적인 0원처럼 표시하지 않는다.

### US-05. 판매가 반영된 재료 잔량을 확인한다

- **사용자가 할 수 있는 일:** 기준일의 재료 잔량과 단위를 확인한다.
- **자동 검사:** 초기재고·기존 입고·폐기·실사·판매 사용량 연결, 포장 전용 재료 적용, 수정·삭제 재계산, 실사 이중 반영 방지.
- **화면에서 확인할 행동:** 판매를 추가·수정·삭제하면서 연결 재료의 잔량을 확인한다.
- **예상 결과:** 승인된 레시피와 실사 정책에 맞춰 잔량이 달라진다. 포장 전용 재료는 해당 채널에만 반영되고, 누락·음수 잔량은 원인을 확인할 수 있다.

**EPIC 1 완료 기준**

실제 저장되는 판매 입력·엑셀 가져오기에서 메뉴 수익성과 재료 잔량까지 연결된다. 새로고침·재접속 후에도 자료가 유지되며, 계산·저장·오류 검사가 통과한다. 화면의 숫자를 고정하거나 저장 안내만 띄우는 방식으로 완료하지 않는다.

## 3. EPIC 2 — 비용과 재고를 반영한 매장 실적

**포함 Story: US-06~US-10, 총 5개**

EPIC 1의 저장·계산 기반을 사용한다.

### US-06. 비용 기록을 관리한다

- **사용자가 할 수 있는 일:** 비용을 직접 추가·수정·삭제하고 날짜·항목별 기록을 확인한다.
- **자동 검사:** 귀속일·항목·금액 검사, 변경·삭제·저장 실패 처리, 재접속 보존, 월계획과 일별 비용의 중복 반영 방지.
- **화면에서 확인할 행동:** 비용 한 건을 저장하고 금액을 수정한 뒤 삭제한다.
- **예상 결과:** 목록과 항목 합계가 바뀐다. 실제 손익 반영은 US-07에서 연결 확인하며, 비용 변경만으로 월계획을 임의 수정하지 않는다.

### US-07. 기간별 매장 실적과 손익을 확인한다

- **사용자가 할 수 있는 일:** 일·주·월·분기·반기·연간의 매출·비용·손익을 확인한다.
- **자동 검사:** 승인된 기간 경계, 직접비·공통비 집계, 계획/실적 이중 합산 방지, 미마감·휴무·실제 0 구분, 부분 연도 표시.
- **화면에서 확인할 행동:** 기간 단위를 바꾸고, 판매·비용을 수정한 뒤 같은 기간의 결과를 확인한다.
- **예상 결과:** 해당 기간의 기록만 집계되고 수정 결과가 반영된다. 미마감 날짜를 매출 0으로 처리하지 않으며 일부 연도 자료라는 사실을 표시한다.

### US-08. 재료 입고를 기록한다

- **사용자가 할 수 있는 일:** 들어온 재료의 날짜·수량 등 승인된 입고 항목을 기록한다.
- **자동 검사:** 재료·단위·수량 검사, 중복 실행 방지, 입고 후 잔량 증가, 저장 실패·재접속 보존.
- **화면에서 확인할 행동:** 재료를 선택해 입고를 저장하고 잔량 화면을 다시 연다.
- **예상 결과:** 해당 재료가 입력 수량만큼 증가하고 다른 재료는 변하지 않는다. 입고 금액을 사용 원가와 이중 비용 처리하지 않는다.

### US-09. 재료 폐기를 기록한다

- **사용자가 할 수 있는 일:** 버린 재료의 수량과 승인된 폐기 항목을 기록한다.
- **자동 검사:** 입력 수량과 저장 감소량 변환, 단위 검사, 잔량 감소, 초과 폐기·음수 잔량의 승인된 처리, 저장 실패.
- **화면에서 확인할 행동:** 폐기를 저장한 뒤 잔량을 확인하고 잔량보다 큰 수량으로도 시도한다.
- **예상 결과:** 정상 폐기는 잔량에 한 번만 반영된다. 초과 폐기는 승인된 규칙대로 안내되며 조용히 0으로 맞추지 않는다. 손익 반영 여부는 확정된 기준을 따른다.

### US-10. 실제로 센 재고를 반영한다

- **사용자가 할 수 있는 일:** 계량하거나 센 실제 잔량을 입력해 장부와의 차이를 반영한다.
- **자동 검사:** 실사 수량 0, 실측량·조정량 이중 반영 방지, 승인된 같은 날 처리 순서, 실사 이전 판매 수정, 저장 실패.
- **화면에서 확인할 행동:** 장부와 다른 실제 수량을 입력한다. 이후 판매를 추가하고 과거 판매도 수정한다.
- **예상 결과:** 실제 계수 수량이 승인된 정책에 따라 기준점으로 반영된다. 이후 거래와 과거 수정 결과가 정책대로 계산되며 가상의 로스 전표를 만들지 않는다.

**EPIC 2 완료 기준**

비용을 반영한 기간 손익과 입고·폐기·실사를 반영한 잔량을 실제 화면에서 확인한다. EPIC 1의 판매 변경도 계속 연결된다. 모든 기록의 재접속 보존과 오류 시 기존 자료 유지가 검증된다.

## 4. EPIC 3 — 전망·발주 참고와 자료 복구

**포함 Story: US-11~US-14, 총 4개**

EPIC 1·2의 판매·비용·달력·재고 자료를 사용한다.

### US-11. 기록 중인 달의 월말 예상 손익을 확인한다

- **사용자가 할 수 있는 일:** 현재 마감 실적과 월말 예상 손익을 구분해 확인한다.
- **자동 검사:** 승인된 표본·영업일·비용 전망 계산, 남은 영업일 0, 표본/달력/월계획 누락, 변경 기록 반영.
- **화면에서 확인할 행동:** 부분 마감된 달의 전망을 열고 판매·비용 변경 후 다시 확인한다.
- **예상 결과:** 기준일·실적·예상이 구분되고 승인된 계산표와 값이 일치한다. 필요한 자료가 없으면 계산 불가 이유가 나온다. 비용 변경의 영향도 승인된 전망 규칙을 따른다.

### US-12. 부족 재료와 참고 발주량을 확인한다

- **사용자가 할 수 있는 일:** 부족 가능 재료를 찾고 구매 묶음 기준의 참고량을 확인한다.
- **자동 검사:** 승인된 평균 사용량·납기·안전재고·구매단위 계산, 충분한 재고·평균 0·구매용량 누락, 경계값과 올림.
- **화면에서 확인할 행동:** 부족 재료를 확인하고 입고를 기록한 뒤 같은 재료를 다시 확인한다.
- **예상 결과:** 부족 판단과 참고 발주량이 갱신된다. 기준단위 수량과 구매 묶음 수가 구분되며, 실제 주문은 전송하지 않는다.

### US-13. 전체 자료를 백업한다

- **사용자가 할 수 있는 일:** 현재 자료 전체를 한 파일로 내려받는다.
- **자동 검사:** 기본 자료·기록·달력·설정 포함, 한 시점의 일관된 자료 내보내기, 형식 버전, 저장 중 백업과 파일 생성 실패.
- **화면에서 확인할 행동:** 기록을 변경한 뒤 백업을 실행하고 파일 다운로드를 확인한다.
- **예상 결과:** 승인된 형식의 실제 파일이 생성된다. 파일 내부 검사로 변경 기록이 포함됐음을 확인하고, 실패를 성공으로 표시하지 않는다.

### US-14. 백업 시점의 전체 자료로 복원한다

- **사용자가 할 수 있는 일:** 백업 파일을 검사하고 확인한 뒤 전체 자료를 되돌린다.
- **자동 검사:** 구조·버전·ID 연결 검사, 취소, 전체 교체와 실패 시 전체 취소, 복원 후 재계산·재접속 보존.
- **화면에서 확인할 행동:** 백업 이후 판매·비용·재고를 변경한 다음 복원한다. 손상된 파일로도 시도한다.
- **예상 결과:** 기록과 계산 결과가 백업 시점으로 돌아가며 기존 자료와 합쳐지지 않는다. 손상 파일·취소·복원 실패에서는 기존 자료가 유지된다.

**EPIC 3 완료 기준**

월말 전망과 부족·발주 참고가 실제 기록으로 계산된다. 전체 백업→자료 변경→복원→재접속을 통과하고, 판매 입력부터 수익성·손익·잔량까지 전체 흐름이 유지된다.

## 5. 모든 Story에 적용할 완료 기준

- 계산은 승인된 FRD 기준과 별도로 작성한 기대값에 대조한다.
- 저장은 같은 기기·브라우저·운영 주소에서 재접속해 확인한다.
- 취소·입력 오류·저장 실패·중복 실행에서 기존 자료가 손상되지 않아야 한다.
- 자동 검사와 사용자의 화면 확인을 모두 통과해야 한다.
- 미정 정책, 가짜 저장, 고정 숫자, 실패한 검사가 있으면 완료 처리하지 않는다.
- 각 EPIC은 실행 가능한 버전으로 제공한다. 최종 GitHub 보관·Vercel 배포 검증은 EPIC 3의 출시 확인에 포함한다. 개발자 작업이므로 별도 사용자 Story로 세지 않는다.
- 시안만의 추가 기능을 구현 범위에 넣지 않는다. 화면과 기술은 PRD·FRD·TRD의 승인 범위를 따른다.

## 6. 필수 기능 대응과 의존성

| PRD/FRD 기능 | Story |
|---|---|
| 기본 자료 사용·조회 / F-00 | US-01 |
| 판매 추가·수정·삭제 / FR-01, F-01 | US-02 |
| 판매 양식 다운로드·가져오기 / FR-02, F-02 | US-03 |
| 비용 추가·수정·삭제 / FR-03, F-03 | US-06 |
| 입고·폐기·실사 / FR-04, F-04 | US-08·09·10 |
| 메뉴 수익성 / FR-05, F-05 | US-04 |
| 기간 실적과 손익 / FR-06, F-06 | US-07 |
| 월말 전망 / FR-07, F-07 | US-11 |
| 잔량·부족 재료 / FR-08, F-08 | US-05·12 |
| 참고 발주 / FR-09, F-09 | US-12 |
| 저장·백업·복원 / FR-10, F-10 | 저장은 모든 기록 Story의 완료 조건, 백업 US-13, 복원 US-14 |

기본 자료와 안전한 저장은 US-01에서 시작하고 이후 모든 기록 기능이 사용한다. US-02·03의 판매가 US-04·05의 결과로 연결된다. US-06의 비용과 EPIC 1 판매를 US-07이 집계하며, US-08~10의 재고 사건은 US-05 잔량에 반영한다. 전망은 판매·비용·달력, 발주 참고는 판매 사용량·잔량·납기·안전재고·구매용량에 의존한다. 백업·복원은 앞선 모든 자료와 연결 결과를 대상으로 한다.

계산·저장·오류 처리·검사는 화면과 함께 구현하는 하위 작업이다. 이를 별도 사용자 Story로 부풀리거나 마지막까지 미루지 않는다.

## 7. 미정 정책과 시간 관리

FRD의 D-01~D-11 승인 상태를 그대로 유지한다. 판매 입력/원가/수수료, 파일 오류·중복, 마감/기간, 실사 순서, 전망 비용, 평균 사용량·발주·반올림, 백업 규격 등 해당 Story의 정책을 구현 전에 결정한다. 숫자 검사표는 승인된 정책으로 작성한다.

4시간은 기존 PRD의 목표로 유지하되, Story 14개로 나눈 것이 4시간 완료를 보장하지는 않는다. 미정 기준 확정이 늦어지거나 검증에 문제가 생기면 필수 기능·저장·정확성 검사를 생략하지 않고 일정 조정을 사용자에게 알린다.

이번 사용자 확인은 개발계획의 저장 승인이다. 개발 실행·GitHub 저장소 생성/푸시·Vercel 배포를 이번 문서 저장 작업에서 실행하지 않는다.
