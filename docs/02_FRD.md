## 1. 문서 읽는 방법과 범위

이 프로그램은 카페의 일자·메뉴·판매채널별 판매 합계, 날짜별 비용, 재료의 입고·폐기·실제 재고를 관리한다. 판매를 입력하면 메뉴별 수익성과 재료 사용량에 반영되고, 비용을 입력하면 매장 전체 손익에 반영된다. 기간 실적과 기록 중인 달의 월말 예상 손익을 구분해 보여주며, 자료를 저장·백업·복원한다.

FRD는 사용자가 무엇을 입력하고 누르면 프로그램이 무엇을 처리하고 어떤 결과를 보여주는지 정리한 문서다. 다음 상태를 구분한다.

- **확정(PRD):** 기존 PRD에서 승인된 기능과 범위. 시안에 없어도 필수다.
- **관찰(시안):** 이미지 또는 HTML에서 실제로 확인한 버튼·입력칸·표시. 구현 승인이나 실제 작동 확인을 뜻하지 않는다.
- **제안(확인 대기):** 이번 문서에서 제안하는 계산식, 입력 규칙, 오류 처리, 상세 동작. 사용자 확인 전 개발 기준으로 확정하지 않는다.
- **충돌/미정:** PRD와 시안이 다르거나 자료만으로 결정할 수 없는 사항.

이 문서의 각 기능에서 '처리 제안', '입력 제안', '예외 처리 제안'은 모두 확인 대기다. 이전 PRD 작성 당시의 '모두 추천' 요청으로 이번 단계의 새로운 계산·추가 기능을 승인된 것으로 처리하지 않는다. PRD나 시안 원본은 수정하지 않았다.

1차 제외 범위는 POS·회계 자동 연동, 실제 발주 실행, 비용·재고 엑셀 가져오기, 자유 형식 파일 해석, 로그인·권한·여러 매장, 메뉴별 공통비 배분이다. 시안에만 있는 추가 기능은 아래 충돌표에 기록하고 1차 확정 요구사항에 넣지 않는다.

## 4. 공통 자료와 처리 원칙

### 4.1 기록의 의미

- 판매 1행은 한 날짜에 같은 메뉴를 같은 채널로 판매한 집계다. 수량 20은 주문 20건을 의미하지 않는다.
- 메뉴·재료·공급사는 각각 ID로 연결한다. 이름이 같아도 임의로 합치지 않는다.
- 금액은 원·부가세 제외, 재료 기준단위는 g·ml·개다. 원가에는 구매 묶음 금액과 개당 금액이 구분된다.
- 실적은 마감 상태와 기록 범위를 함께 보여준다. '자료 없음', '미마감', '휴무', '실제 0'은 서로 다르다.
- 자료 기준일은 마지막 확인된 마감 기록을 뜻한다. 컴퓨터의 오늘 날짜로 샘플의 기준일을 바꾸지 않는다.
- 변경된 판매는 메뉴 수익성·매장 손익·재료 잔량·전망/발주 참고 결과와 연결된다. 비용 변경은 손익과 전망에 연결된다.

### 4.2 공통 상세 동작 제안

- 저장 전 검사를 통과해야 기록을 바꾼다. 저장 실패 시 기존 자료를 보존하고 입력값·실패 원인을 보여준다.
- 저장과 연결 계산이 끝난 후 성공 안내를 표시한다. 처리 중에는 같은 버튼을 여러 번 눌러 중복 등록하지 못하게 한다.
- 취소/닫기는 저장하지 않는다. 입력값이 바뀐 경우 버릴지 확인하는 안을 권장한다.
- 삭제는 대상과 영향을 확인한 뒤 처리한다. 취소하면 자료와 계산 결과를 유지한다.
- 변경 시 원본 엑셀·JSON 파일을 덮어쓰지 않는다. 프로그램의 저장 자료를 갱신하며 파일 다운로드는 지정된 기능에서만 한다.
- 계산 입력이 빠지면 0으로 대체하지 않고 '계산 불가: ○○ 누락'을 표시한다. 일부 메뉴가 계산 불가이면 전체 합계를 완전한 값처럼 표시하지 않는다.
- 재료 잔량은 현재/기준일 시점의 양이다. 월별 잔량을 더해 연간 잔량을 만들지 않는다.

## 5. 기능별 상세 요구사항

### F-00. 기본 자료 최초 사용·조회

**확정:** 제공된 가상 매장 샘플을 하나의 형식으로 한 번만 불러온다. 메뉴 8개, 재료 11개, 공급사 3개와 레시피·가격 이력을 조회한다. 기본 자료 편집은 2차다.

**사용자 행동과 결과 제안:** 처음 실행하면 샘플을 사용하고, 기본 자료 조회를 선택하면 각 ID와 이름·단위·가격·레시피 연결을 보여준다. 기존 저장 자료가 있으면 다시 샘플로 초기화하지 않는다. 초기 로딩 형식은 제공 JSON 하나를 권장하며 별도 자유 형식 업로드 기능을 만들지 않는다. 저장 결과에는 초기재고·달력·월계획·과거 기록과 출처도 포함한다. 새 다운로드 파일은 만들지 않는다.

**예외 처리 제안:** 샘플 손상, 중복 ID, 레시피에 없는 메뉴/재료, 단위 불일치는 원인과 대상을 알리고 관련 계산을 보류한다. 일부만 읽은 상태를 정상 완료로 표시하지 않는다. 가격 이력이 없는 메뉴는 해당 원가가 계산 불가임을 표시한다.

**미정:** 시안에 없는 기본 자료 조회 진입 위치, 최초 로딩 형식의 최종 선택.

### F-01. 판매 기록 조회·추가·수정·삭제

**확정:** 날짜·메뉴·채널별 판매 집계를 직접 추가·수정·삭제하며 변경을 수익성·손익·재고에 반영한다.

**관찰:** `_2` 목록과 수정·삭제 버튼, `_3` 판매 추가 팝업. `_2`와 `_3`의 순매출 입력 방식이 다르다.

**입력 제안:** 판매일, 실제 메뉴 선택, 매장/포장, 판매수량, 판매 당시 단가, 할인 총액, 결제 수수료 실제 금액. 날짜·메뉴·채널·수량은 필수. 단가는 메뉴 기준가를 초깃값으로 보여주되 수정 가능하게 하는 안을 권장한다. 순매출은 계산 결과로 표시한다. 수수료의 직접 입력 대 자동 비율 계산은 미정이다. 이 필드 구성은 시안 변경을 포함하므로 확인 대기다.

**처리와 결과 제안:**

1. '판매 기록 직접 추가'에서 입력창을 연다. 메뉴·수량·단가·할인·채널 변경 시 순매출, 적용 레시피의 재료 사용량과 원가를 미리 보여준다. 미리보기는 재고를 바꾸지 않는다.
2. 저장하면 새 기록 ID, 입력 금액, 적용 레시피 버전, 계산한 개당 원가를 보존하고 목록·메뉴 결과·기간 손익·잔량을 갱신한다.
3. 수정은 같은 기록 ID를 유지하고 기존 영향을 제거한 후 수정된 영향을 반영한다. 날짜·메뉴·채널 변경 시 이전 대상과 새 대상 모두 갱신한다.
4. 삭제는 해당 판매의 영향을 제거하고 관련 결과를 다시 계산한다. 재고 사용량을 다시 추가로 빼는 방식으로 처리하지 않는다.
5. 파일을 만들지는 않으며 프로그램 저장 자료와 다음 백업에 반영한다.

**조회 상세 제안:** 날짜 범위·채널·메뉴·검색어를 함께 적용한다. 상단 합계는 검색 결과 전체, 하단 '현재 페이지 합계'는 보이는 행만 집계한다. 수량은 '판매 개수'로 표시하고 잔/개의 구분을 유지한다. 필터 변경 시 첫 페이지로 이동하고, 초기화/X는 해당 조건을 해제한다. 페이지 버튼은 첫·마지막에서 추가 이동하지 않는다. 검색/페이지 기능은 관찰된 조회 상세이며 1차 구현 수준은 확인 대기다.

**예외 처리 제안:** 날짜 누락·불가능한 날짜·알 수 없는 메뉴/채널·숫자 아닌 값은 저장하지 않는다. 수량은 양의 정수, 할인은 0 이상의 금액이며 판매금액 초과 할인은 오류로 표시하는 안을 권장한다. 시안처럼 음수가 된 순매출을 조용히 0으로 바꾸지 않는다. 환불/반품의 음수 판매는 PRD에 없으므로 새 기능으로 처리하지 않는다. 같은 날짜·메뉴·채널이 이미 있으면 중복 가능성을 알리고 등록을 보류하는 안을 권장한다. 취소·검증 실패·연속 클릭으로 중복 기록을 만들지 않는다.

**미정:** 순매출 입력 방식, 신규 원가·수수료, 중복 합계의 수정/추가 방식, 미마감일·휴무일·미래일 입력 정책, 새 날짜의 달력/마감 반영. 과거 마감일 변경 자체를 금지하는 규칙은 아직 없다. 마감 기능을 확인 없이 새로 추가하지 않는다.

### F-02. 판매 엑셀 양식 다운로드·검사·가져오기

**확정:** 정해진 판매 양식을 내려받아 판매만 가져온다. 필수값 누락·알 수 없는 메뉴·단위 오류·중복 위험을 등록 전 알린다. 오류를 조용히 제외하거나 0으로 바꾸지 않는다.

**관찰:** `_2` 다운로드/가져오기, `_4` 파일 교체·검증 목록·중복 체크·등록 실행.

**양식 제안:** .xlsx 한 종류, 첫 행은 열 이름, 다음 행부터 날짜·메뉴ID·채널·수량·판매단가·할인총액·수수료금액을 입력한다. 메뉴ID와 채널의 사용 가능한 값과 금액 단위를 안내한다. 계산 결과인 순매출·원가는 입력과 구분한다. 새 양식의 열 구성, 파일명, 선택 항목은 확인 대기다. 원본 전체 운영 엑셀과 판매 입력 양식을 같은 파일 규격으로 간주하지 않는다.

**처리와 결과 제안:** 다운로드를 누르면 양식 파일을 만든다. 파일 선택/교체 후 검사하면 파일명, 총 데이터 행 수, 정상·오류·중복 수, 원본 엑셀 행 번호·문제 열·이유를 보여준다. 검사만으로 저장·재고 변경하지 않는다. 확인된 등록 대상 수로 버튼을 표시하며, 확정 실행 후 결과 건수와 관련 실적·재고를 갱신한다. 파일 교체 시 이전 파일의 검사 결과를 지운다. 취소하면 파일을 등록하지 않는다.

**권장 등록 정책(미정):** 오류가 하나라도 있으면 전체 등록을 보류하고 원본 파일 수정 후 다시 검사한다. 중복도 기본 보류하여 기존 자료를 덮어쓰거나 수량을 더하지 않는다. `_4`의 정상 행만 등록/중복 건너뛰기는 다른 선택지이므로 승인이 필요하다. 단순히 파일명이 같은지만 보지 않고 기록 ID가 있으면 ID, 없으면 날짜·메뉴·채널을 기준으로 중복 가능성을 검사한다.

**예외 처리 제안:** 파일 미선택, 손상/암호 파일, 다른 형식, 필수 열 없음, 빈 파일, 날짜가 숫자/문자 형식으로 섞임, 파일 안 중복, 기존 기록과 중복을 알린다. 엑셀 날짜는 실제 날짜로 해석하고 혼동되는 날짜는 오류로 돌린다. 계산 입력 열의 수식·숨은 행 처리, 파일 용량/행 수 상한은 별도 결정한다. 등록 중 저장 실패 시 일부만 저장된 성공 상태를 만들지 않는 안을 권장한다. 오류 파일 다운로드 기능은 2차이므로 이 단계에서 추가하지 않는다.

**파일 결과:** 양식 .xlsx만 확정 범위다. 가져오기는 업로드 파일을 수정하지 않고 프로그램 자료에 기록한다.

### F-03. 비용 기록 조회·추가·수정·삭제

**확정:** 비용을 직접 추가·수정·삭제하고 기간별·항목별로 조회한다. 월비용계획과 일별 비용은 같은 비용이므로 이중 합산하지 않는다. 비용 엑셀은 2차다.

**입력 제안:** 귀속일(어느 날의 비용인지), 제공 자료의 8개 비용항목 중 선택, 원 단위 금액. ID는 프로그램에서 관리한다. 메모 추가나 새로운 비용 분류는 승인 없이 넣지 않는다.

**처리와 결과 제안:** 날짜·항목·금액 검사 후 저장하고 목록·항목별 합계·기간 손익·월말 전망을 갱신한다. 수정은 해당 기록을 교체, 삭제는 그 기록만 제거한다. 기존 월계획을 자동으로 늘리거나 새로운 일할 비용을 만들지 않는다. 같은 날짜에 같은 항목의 비용이 여러 개 있는 경우 합산할지/기존 배분 비용을 수정할지 별도 확인한다. 저장 자료만 바뀌며 다운로드 파일은 만들지 않는다.

**예외 처리 제안:** 날짜·항목 누락, 숫자 아닌 금액, 음수 금액은 저장 보류를 권장한다. 실제 0원과 미입력을 구분한다. 환급 비용을 음수로 다룰지 미정이다. 기존 샘플의 일할 배분 기록과 같은 비용을 또 입력하는 경우 중복 가능성을 알려준다. 비용 삭제 후 월계획으로 실적 비용을 자동 대체하지 않는다.

**미정:** 비용 화면/입력 배치, 월계획 대비 일별 실적의 최종 적용 규칙, 월 비용 일괄 입력/자동 일할 배분은 1차에 추가할지 별도 승인 필요.

### F-04. 입고·폐기·실제 재고 기록

**확정:** 입고·폐기·실제 계수 수량을 기록한다. 판매 레시피와 채널을 연결하고 실제로 센 재고를 기준으로 차이를 조정한다.

**관찰:** `_5`의 '재고 변동 입력(입고/폐기/실사)'와 재료별 '실사'. 입력창은 시안에 없다. 재고 기록 수정·삭제는 PRD에 명시되지 않았으므로 필수로 추가하지 않는다.

**입력 제안:** 일자, 재료, 입고/폐기/실사 유형과 해당 재료의 기준단위 수량. 입고는 공급사·단위원가, 폐기는 사유, 실사는 실제로 센 잔량을 입력한다. 각각의 선택/필수 여부는 확인 대기다. 폐기는 사용자가 양수로 입력하고 저장 시 감소량으로 바꾸는 안을 권장한다. 실사 입력 0은 실제 품절을 의미한다.

**처리와 결과 제안:** 유형에 맞는 입력을 검사하고 기록 ID를 부여한다. 입고는 잔량 증가, 폐기는 잔량 감소, 실사는 계산 잔량과 실제 수량의 차이를 반영한다. 일자·재료·유형·증감량·단위·실사 시 실제 수량을 저장하고 잔량·부족 상태·발주 참고를 갱신한다. 파일 생성은 없다. 실사 차이를 자동 회계 전표나 추가 손익 비용으로 만들지 않는다.

**예외 처리 제안:** 재료 누락·단위 불일치·숫자 아닌 수량은 저장하지 않는다. 입고/폐기는 양의 수량, 실사는 0 이상의 수량을 권장한다. 잔량보다 많은 폐기/계산 잔량 음수는 원인 확인을 안내한다. 자동으로 0으로 맞추지 않는다. 재고 부족을 이유로 실제 판매 기록을 삭제하거나 숨기지 않는다.

**미정:** 하루 중 실사 시점, 같은 날 여러 실사 순서, 과거 판매 수정 시 실사 이후 잔량 처리, 폐기/실사 차이의 비용 반영, 입고 가격이 가격 이력을 자동 갱신할지. 1차는 자동 가격 이력 편집을 추가하지 않는 안 권장.

### F-05. 메뉴별 수익성 조회

**확정:** 메뉴별 판매량·매출·직접 비용을 고려한 수익성을 보여준다. 임차료·인건비는 메뉴에 배분하지 않는다.

**관찰:** `_1`의 메뉴 표와 '개당 공헌이익·공헌이익률'. 공헌이익은 판매금액에서 식재료·포장재·수수료를 고려한 남는 금액을 뜻하며 매장 전체 순이익과 다르다.

**처리와 결과 제안:** 선택 기간의 대상 판매를 메뉴ID로 모아 판매개수·순매출·식재료비·포장비·수수료·남는 금액·개당 금액·비율을 계산한다. 과거 판매 원가는 기록된 개당 원가를 이용한다. 분류/검색을 지원하는 경우 해당 메뉴 표만 좁히고 매장 전체 손익과 혼동하지 않도록 합계 범위를 표시한다. 파일 생성은 없다.

**예외 처리 제안:** 판매수량 0이면 개당 결과는 '해당 없음', 순매출 0이면 비율은 '해당 없음'이다. 원가/수수료 누락은 해당 결과 계산 불가로 표시한다. 판매가 없는 메뉴를 0 판매로 보여줄지는 미정이며 수익성이 낮다고 자동 분류하지 않는다.

**미정:** '효자/개선 필요' 등급은 승인된 기준이 없다. 자동 수익 등급·BEP·목표 달성·전월 비교는 확인 없이 추가하지 않는다.

### F-06. 기간별 실적과 매장 손익

**확정:** 일·주·월·분기·반기·연간 조회. 마감 실적·미마감·휴무와 일부 연간 자료를 구분한다.

**관찰:** `_1`의 기간 탭과 선택 월. 다른 기간으로 이동/선택하는 조작은 시안에 상세히 없다.

**입력/처리 제안:** 기간 단위와 기준 날짜를 선택하면 해당 시작·종료 날짜를 계산하고 같은 범위의 판매·직접 비용·일별 비용을 집계한다. 기간 합계, 메뉴 합계, 비용 항목별 합계가 같은 대상 기록을 사용한다. 기간 선택 변경은 기록을 수정하지 않는다.

**화면/파일 결과:** 기간 이름, 실제 포함한 기록 범위, 마감 범위와 누락 여부, 순매출·식재료비·포장비·수수료·공통비·매장 손익을 표시한다. 부분 연도는 '2025년 7~12월 자료만 포함'과 같이 표시한다. 보고서 PDF는 미승인 추가 기능이므로 파일 생성은 없다.

**예외 처리 제안:** 시작일이 종료일보다 늦으면 조회하지 않고 입력 오류를 알린다. 자료 범위 밖과 미마감 기간은 '자료 없음/미마감'으로 표시하며 0 실적이나 적자로 단정하지 않는다. 월별 비율을 더하거나 단순 평균하지 않고 전체 금액으로 다시 계산한다. 마감 영업일에 판매가 누락되었는지와 실제 0인지 판별할 수 없으면 누락 가능성을 알린다.

**미정:** 주 시작 요일, 달력연도/회계연도, 미마감 입력을 목록에는 보이되 실적에서는 제외할지, 마감 상태를 어떤 조작으로 갱신할지. 상세 마감 기능은 PRD 2차와 충돌하므로 자동 추가하지 않는다.

### F-07. 기록 중인 달의 월말 예상 손익

**확정:** 월말 예상 하나만 제공하고 실제 실적과 구분한다. 모든 기간 예측은 2차다.

**처리 제안:** 마지막 마감일이 속한 달의 마감된 영업일 실적을 표본으로 남은 예정 영업일의 순매출과 직접 비용을 예상한다. 월 비용 계획을 월말 공통비 전망으로 사용하되 이미 실적에 포함한 일별 비용을 또 더하지 않는다. 실제와 남은 기간 예상, 월말 합계를 구분해 표시한다.

**화면/파일 결과 제안:** 기준 마감일, 표본 영업일 수, 남은 영업일 수, 월말 예상 순매출·직접 비용·공통비·손익과 전망 방법을 표시한다. 오늘 날짜가 10월이어도 샘플은 9월 18일 기준 9월 전망이라고 표시한다. 파일 생성은 없다.

**예외 처리 제안:** 마감된 영업일이 0이면 계산 불가. 표본이 적으면 사용한 일수와 참고 전망임을 표시한다. 남은 달력이 없거나 월비용계획이 없으면 해당 예측이 계산 불가임을 알린다. 남은 영업일이 0이면 남은 판매 예상은 0이지만 미마감/비용 누락 여부를 별도로 표시한다. 기상·행사·프로모션 보정은 자료에 메모가 있어도 확인 없이 적용하지 않는다.

**미정:** 당월 평균 대 최근 기록 평균, 표본 최소일수, 월계획 없는 달의 처리, 입력한 비용을 월계획에 어떻게 반영할지. 계산 제안은 6절에 명시한다.

### F-08. 재료 잔량·부족 재료 조회

**확정:** 재료별 잔량과 부족 가능 재료를 보여준다. 판매·입고·폐기·실사의 영향을 포함한다.

**관찰:** `_5` 잔량 표, 부족 안내, 검색/분류/상태 선택, 이력 버튼. 재료 분류는 실제 자료에 별도 필드가 없어 시안 분류를 임의로 부여하지 않는다.

**처리와 결과 제안:** 기준일을 표시하고 초기재고부터 해당 시점까지 재료별 사용/변동을 반영한다. 표에는 실제 재료명·기준단위·잔량·납기·안전재고·예상 사용과 부족 판단 근거를 표시한다. 검색을 제공하면 재료명·공급사명·ID를 각각 검색하고 선택 조건을 함께 적용한다. 이력은 이미 저장된 해당 재료 기록을 읽기만 하는 안으로 제안하며 별도 편집 기능을 넣지 않는다.

**예외 처리 제안:** 초기재고 누락, 단위 혼합, 레시피 없음이면 해당 잔량 계산을 보류한다. 음수 잔량은 기록 점검이 필요한 상태로 보여준다. 평균 사용이 0이면 '소진일 계산 불가/최근 사용 없음'으로 표시하고 충분한 재고라고 단정하지 않는다. 필터 결과 0건은 '조건에 맞는 재료 없음'이며 재료 삭제가 아니다.

**파일 결과:** 조회 자체는 파일을 만들지 않는다. Excel 원장 다운로드는 PRD 필수 범위가 아니다.

### F-09. 참고 발주량 조회

**확정:** 사용량·잔량·납기·안전재고 영업일·구매용량을 고려한 참고량을 제공한다. 운영자가 발주를 판단하며 주문을 보내지 않는다.

**처리/결과 제안:** 재료마다 예상 필요량에서 잔량을 고려하고 음수가 아닌 구매 묶음 수로 올림한다. '기준단위 필요량', '구매 묶음 수', '구매 환산량'을 구분한다. 부족 판정 근거와 사용한 평균 기간을 함께 보여준다. `_5`의 박스 크기를 사용하지 않고 실제 자료의 구매용량을 사용한다.

**예외 처리 제안:** 구매용량 0/누락, 납기·안전재고 누락, 사용 표본 없음은 계산 불가. 재고가 충분하고 근거가 모두 있으면 참고량 0이다. 납기기간 내 달력 정보가 없으면 예상 입고 날짜를 단정하지 않는다. 발주 예정/주문 중 재고는 PRD와 원본에 없으므로 계산에서 임의로 빼지 않는다.

**파일 결과:** 참고 조회만 제공한다. '발주담기/긴급 발주서 작성/복사/인쇄/발주금액'은 승인 전 기능이므로 1차 동작으로 확정하지 않는다.

### F-10. 저장·전체 백업·전체 복원

**확정:** 입력·수정 자료를 다음 접속에서도 유지한다. 기본 자료·기록·달력·설정 전체를 한 파일로 백업하고, 복원 시 기존 전체 자료를 백업 시점 자료로 교체한다.

**시안 상태:** 메뉴만 있고 상세 화면과 파일 규격은 없다.

**처리/결과 제안:** 기록의 저장 성공 시 보존을 완료한다. 다시 열면 저장 자료를 읽고 샘플을 덧붙이지 않는다. 백업 실행 시 저장이 끝난 자료 전체와 자료 형식 버전·기준일·생성시각을 포함한 파일을 내려준다. 파일명은 `prep_cafe_backup_YYYYMMDD_HHMMSS.json`을 제안하며 원본 샘플 JSON과 복원용 파일을 구별한다.

복원은 파일 선택 → 구조·필수 자료·ID 연결·형식 버전 검사 → 교체될 자료 안내 → 사용자 확인 → 전체 교체 → 결과 재계산 순서를 제안한다. 취소는 교체하지 않는다. 복원 성공 후 기준일·기록 수를 보여주며, 과거 판매 원가 기록은 그대로 유지한다. 복원은 기존과 병합하거나 선택 항목만 덮어쓰지 않는다.

**예외 처리 제안:** 파일 미선택, 손상 JSON, 필수 목록 누락, 중복/알 수 없는 ID, 지원하지 않는 버전은 현재 자료를 유지하고 이유를 표시한다. 빈 목록은 실제 0건인지 목록 자체 누락인지 구분한다. 파일 검사가 통과해도 저장 공간 부족·처리 실패가 나면 기존 자료를 복구하고 성공으로 표시하지 않는다. 저장 중 백업은 저장 완료 후 실행하도록 하는 안 권장. 다운로드 요청이 완료되었다는 안내와 실제 사용자 디스크 저장 확인은 구분한다.

**미정:** 자동 저장 대 별도 저장 버튼, 파일 규격/버전 호환 범위, 기기·브라우저를 바꿨을 때 유지 범위. 로그인·클라우드 공유·자동 백업은 새 필수 기능으로 추가하지 않는다.

## 6. 계산 방법 제안 — 전부 사용자 확인 대기

### C-01. 판매금액과 과거 기록

- 신규 순매출 = 판매수량 × 판매 당시 단가 − 할인 총액.
- 할인은 개당 금액이 아니라 해당 집계행 전체 금액으로 입력하는 안을 권장한다.
- 과거 순매출·수수료·개당 원가는 원본 값을 유지하고 이상 차이는 알려준다. 새 기준가로 과거 판매를 일괄 다시 계산하지 않는다.
- 수량/채널/메뉴/판매일 수정 시 어떤 원가를 유지·갱신할지는 결정 필요하다.

예: 4,800원 라떼 10개에 할인 총액 1,000원이면 순매출은 47,000원. 수수료는 기록된 실제 금액을 사용하는 안을 우선 추천한다. 자동 비율 계산을 선택하더라도 시안의 3.0%/3.3%를 승인 없이 사용하지 않는다.

### C-02. 신규 판매 원가와 메뉴 수익성

1. 판매일에 적용 가능한 가격 이력 중 가장 최근 시작일의 구매가격/구매용량을 찾는다.
2. 재료 기준단위당 원가 = 구매가격 ÷ 구매용량.
3. 개당 식재료/포장 원가 = 해당 레시피 사용량 × 재료 단위당 원가의 합계. 모든 채널 공통 행과 선택 채널 전용 행만 포함한다.
4. 식재료비 = 판매수량 × 기록된 개당 식재료 원가. 포장비도 동일하다.
5. 메뉴별 남는 금액 = 순매출 − 식재료비 − 포장비 − 결제 수수료.
6. 개당 남는 금액 = 메뉴별 남는 금액 ÷ 판매개수. 비율 = 남는 금액 ÷ 순매출 × 100.

식재료와 포장재 구분은 원본의 명시적 분류가 부족하므로 재료 ID별 분류를 확인해야 한다. '채널 전용'이라는 이유만으로 모든 재료를 포장재로 단정하지 않는다. 여러 가격으로 팔렸을 때 기준가 한 개를 개당 수익으로 사용하지 않고 실제 합계에서 구한다. 메뉴별 임차료/인건비를 나누지 않는다.

예: 순매출 47,000원, 식재료비 10,000원, 포장비 1,600원, 실제 수수료 700원이면 남는 금액 34,700원, 개당 3,470원이다. 이 숫자는 설명용 예시이며 원본 샘플의 검증값이 아니다.

### C-03. 기간 손익과 공통비

- 직접 비용 = 판매에 연결된 식재료비 + 포장비 + 수수료.
- 매장 공통비 실적 = 선택 기간의 일별 비용 기록 합계.
- 매장 손익 = 순매출 합계 − 직접 비용 합계 − 공통비 실적.
- 월계획은 실적 비용과 더하지 않는다. 같은 비용의 두 표현이므로 실적과 전망 역할을 분리한다.
- 원재료 구매 금액을 식재료 사용 원가와 동시에 또 비용 처리하지 않는 안을 권장한다.
- 폐기·실사 차이의 손익 반영은 PRD에서 확정되지 않았다. 1차 손익 포함 여부를 확인하기 전 시안의 '자동 로스 전표'는 사용하지 않는다.

공통비는 휴무일에도 발생할 수 있으므로 일별 비용을 영업일만 남겨 집계하지 않는 안을 권장한다. 부분 기간이면 해당 기간 일별 비용만 사용한다. 비용 기록 누락을 월계획으로 자동 메우지 않는다.

### C-04. 기간 경계와 마감

추천 경계는 일 1일, 주 월요일~일요일, 월 해당 달 1일~말일, 분기 1~3/4~6/7~9/10~12월, 반기 1~6/7~12월, 연 1~12월이다. 시작·종료일을 포함한다. 이 경계는 아직 확인 대기다.

판매 집계의 마감 상태와 비용 귀속일을 함께 보여주고, 중간에 미마감일이 있으면 '18일 전체 마감'처럼 단정하지 않는다. 실제 0원은 마감 여부와 기록 완결성을 확인할 수 있어야 한다. 하루의 기록 완결성을 설정하는 방식은 별도 결정이 필요하다.

### C-05. 월말 전망

추천안은 해당 월의 마감된 영업일 평균이다.

- 평균 순매출 = 해당 월 마감 영업일의 순매출 합계 ÷ 마감 영업일 수.
- 평균 직접 비용 = 같은 대상 영업일 직접 비용 합계 ÷ 같은 영업일 수.
- 월말 예상 순매출 = 현재 실적 순매출 + 평균 순매출 × 남은 예정 영업일 수.
- 월말 예상 직접 비용 = 현재 실적 직접 비용 + 평균 직접 비용 × 남은 예정 영업일 수.
- 월말 예상 공통비 = 해당 월 비용 계획 합계. 실적 일별 비용을 여기에 또 더하지 않는다.
- 월말 예상 손익 = 월말 예상 순매출 − 월말 예상 직접 비용 − 월말 예상 공통비.

영업 달력의 휴무일은 평균의 영업일 분모와 남은 영업일에 넣지 않는다. 실제 마감된 영업일의 판매 0은 확인된 경우 분모에 포함한다. 이 방식은 비용 계획을 유지하므로 추가 비용 입력이 월말 계획에도 반영되어야 하는 상황은 별도 규칙이 필요하다. 월계획 수정 기능을 확인 없이 추가하지 않는다.

예: 마감 영업일 10일 순매출 1,000,000원, 남은 영업일 5일이면 월말 예상 순매출은 1,500,000원이다. 날짜 15일을 무조건 영업일 15일로 세지 않는다.

### C-06. 재료 사용·잔량·실사

- 재료 사용량 = 메뉴 판매수량 × 적용 레시피의 개당 재료 사용량. 공통 행과 선택 채널 행만 반영한다.
- 실사 전 장부 잔량 = 초기재고 + 입고 − 판매 사용량 − 폐기 + 실사조정.
- 입고/폐기/판매를 처리한 하루의 마감 후 실사로 보는 안을 추천한다.
- 실사조정량 = 실제로 센 수량 − 실사 직전 장부 잔량. 실사 후 잔량은 실제로 센 수량이다.
- 과거 기록의 증감량과 실측수량을 이중으로 더하지 않는다. 실측수량을 잔량 기준점으로 삼거나 조정량을 적용하는 한 가지 방식으로 처리한다.
- 이후 판매/입고/폐기는 그 실사 잔량부터 반영한다. 실사 이전의 판매를 수정하면 그날까지의 차이는 바뀌지만 실사에서 실제로 센 수량은 유지하는 안을 권장한다.

예: 장부 우유 5,000ml를 실제로 4,500ml로 세었다면 조정 −500ml를 반영한다. 4,500ml를 입고처럼 더하지 않는다. 같은 날 실사가 여러 번 있거나 날짜만으로 순서를 알 수 없는 경우 적용 순서는 결정 대기다.

### C-07. 부족 판정·소진 예상·참고 발주

추천 평균은 최근 마감된 7영업일의 판매 레시피 사용량이다. 7일 미만이면 실제 표본 수를 표시하고, 미마감일은 평균에 0으로 넣지 않는다. 입고·폐기·실사 차이를 판매 사용량 평균에 섞지 않는 안을 권장한다.

- 일평균 사용량 = 표본 영업일의 판매 레시피 사용량 ÷ 표본 영업일 수.
- 안전재고량 = 일평균 사용량 × 안전재고 영업일 수.
- 납기 동안 예상 사용량 = 일평균 사용량 × 납기 영업일 수.
- 기준 목표량 = 안전재고량 + 납기 동안 예상 사용량.
- 부족 참고량 = 최대(0, 기준 목표량 − 현재 잔량).
- 구매 묶음 수 = 부족 참고량 ÷ 구매용량을 올림.
- 환산 발주량 = 구매 묶음 수 × 구매용량.
- 소진 예상 영업일 수 = 잔량 ÷ 일평균 사용량. 평균 0이면 숫자 대신 최근 사용 없음으로 표시한다.

부족 가능성은 목표량보다 잔량이 작은 경우, 납기 이전 품절 위험은 납기 예상 사용량보다 작은 경우로 설명하는 안을 제안한다. 시안의 '주의 3일대' 같은 임의 등급은 사용하지 않는다. 등급 수와 경계는 사용자 확인 대기다.

예: 하루 2,000ml 사용, 납기 1영업일, 안전재고 1영업일, 현재 3,000ml, 구매용량 1,000ml이면 참고 구매량은 1묶음=1,000ml다. 시안의 24팩 박스를 원본에 없는 최소 주문량으로 만들어 적용하지 않는다.

### C-08. 표시와 반올림

금액은 화면에서 원 단위, g/ml는 필요한 소수 자리, 개 단위는 정수로 보이는 안을 권장한다. 원가 계산은 중간 단계에서 반복 반올림하지 않고 합산한 후 표시한다. 최종 합계와 표시된 행 합계의 차이 처리, 금액 반올림 방식, 개당 금액/비율 소수 자리는 결정 대기다. 원본 숫자와 저장된 과거 금액을 표시 편의로 바꾸지 않는다.

## 7. 화면 결과와 파일 결과의 범위

| 사용자 행동 | 화면 결과 | 저장 자료 / 파일 결과 |
|---|---|---|
| 판매 추가·수정·삭제 | 기록 목록, 수익성, 실적·손익, 재고·참고량 갱신 | 판매 자료 갱신. 원본 파일 변경 없음 |
| 비용 추가·수정·삭제 | 비용 목록·항목 합계·손익·전망 갱신 | 비용 자료 갱신 |
| 입고·폐기·실사 입력 | 해당 재료 잔량·부족·발주 참고 갱신 | 재고 사건과 실제 계수 수량 보존 |
| 기간/메뉴/재료 조회 | 조건에 맞는 결과와 합계 | 기록 변경·파일 생성 없음 |
| 판매 양식 다운로드 | 다운로드 요청 안내 | 판매 입력용 .xlsx |

| 검사 후 가져오기 실행 | 등록 결과와 연결 결과 | 승인된 정책에 따라 판매 자료 갱신 |
| 저장 완료 | 저장 상태 | 다음 접속에서도 유지되는 전체 자료 |
| 전체 백업 | 백업 기준일·다운로드 안내 | 전체 자료 백업 파일. JSON 규격은 제안 |
| 전체 복원 | 교체 확인·복원 결과·갱신된 결과 | 기존 전체 자료를 검증된 백업으로 교체 |

PDF 보고서, 비용·재고 Excel, 발주서 파일, 자동 회계 전표는 1차 확정 파일 결과에 포함하지 않는다.

## 8. 공통 오류·경계 조건

아래는 처리 제안이다. 확정 전에는 구현값으로 단정하지 않는다.

| 상황 | 권장 동작 |
|---|---|
| 필수 입력 누락/형식 오류 | 해당 입력칸/엑셀 행과 이유 안내, 저장 보류, 입력 유지 |
| 존재하지 않는 ID/연결/레시피 | 해당 기록 보류. 기존 정상 자료 유지 |

| 검사 후 실행 전에 자료가 바뀜 | 중복·연결 조건을 다시 확인하고 결과 달라지면 확정 실행 보류 |
| 저장 실패/처리 중단 | 성공 표시 금지. 기존 자료 보존, 실패 이유·재시도 안내 |
| 이중 클릭 | 처리 중 동일 실행 제한. 같은 기록을 두 번 만들지 않음 |
| 데이터 없음/검색 0건 | '자료 없음'과 '조건에 맞는 결과 없음'을 구분 |
| 미마감/휴무/실제 판매 0 | 별도 상태로 표시. 미래를 매출 0으로 넣지 않음 |
| 분모 0/원가 누락/가격 이력 없음 | 해당 결과 계산 불가 또는 해당 없음. 전체 결과를 건강한 0으로 꾸미지 않음 |
| 단위 불일치 | g·ml·개 사이 임의 환산 금지. 올바른 단위 안내 |
| 음수 재고 | 계산값 유지·기록 점검 안내. 판매를 자동 취소하거나 잔량을 0으로 고치지 않음 |
| 삭제/복원 취소 | 저장·화면 결과 유지 |
| 입력 중 이동·새로고침 | 미저장 입력의 처리 규칙 확인. 새로고침을 POS 동기화로 안내하지 않음 |

### D-01. 1차에서 시안의 추가 기능을 어떻게 다룰 것인가?

- **A — PRD 우선(추천):** 판매·수익성·손익·재고·엑셀·저장·백업·복원에 집중한다. POS 연동, PDF, 발주서, 자동 로스 전표 등 추가 기능은 보류하고, 시안의 메뉴·가격은 실제 자료로 맞춘다.
- **B — 추가 기능도 검토:** 먼저 포함할 추가 기능을 사용자와 정하고 PRD/4시간 범위를 조정한다. 예: PDF가 꼭 필요하면 추가 시간을 확보하거나 다른 기능 범위를 줄이는 결정을 한다.

추천 이유: A는 이미 정한 필수 기능을 빠뜨리지 않으면서 4시간 MVP의 범위를 지킬 수 있다. 시안에 버튼이 있다는 이유로 POS 연결이나 발주 작업까지 개발하는 일을 막는다. B를 선택해도 추가 기능 전체가 자동 승인되는 것은 아니다.

## 11. EPIC 1 구현 승인 보충 — 2026-10-12

사용자의 개별 추천 답변과 “최적화시켜서 추천으로 해줘”에 따라 아래 EPIC 1 기준을 적용한다. 앞의 확인 대기 표 중 아래에 해당하는 내용만 승인으로 갱신하며, EPIC 2·3의 전망·발주·비용·백업 정책은 이번 작업에서 확정하지 않는다. 새 기능도 추가하지 않는다.

- 판매 순매출은 실제 판매단가 × 판매수량 − 할인 총액. 실제 결제 수수료는 직접 입력한다.
- 신규 원가는 판매일의 재료 가격 이력·레시피로 계산한다. I10·I11은 포장 원가로 구분한다. 기존 기록은 날짜·메뉴·채널이 같으면 당시 원가를 유지하고 이 값이 바뀌면 다시 계산한다.
- 직접 입력과 파일 가져오기는 마감된 영업일만 허용한다. 휴무·미마감·달력에 없는 날짜는 이유를 표시하고 보류한다. 마감 갱신 기능을 추가하지 않는다.
- 같은 날짜·메뉴·채널 또는 오류가 하나라도 있으면 전체 등록을 보류한다. 부분 등록·자동 합산·덮어쓰기는 하지 않는다.
- 판매 .xlsx 필수 열은 일자, 메뉴ID, 판매채널, 판매수량, 판매단가, 할인총액, 결제수수료다. 할인·수수료가 없어도 0을 적는다. 수식·숨은 행·잘못된 날짜·복잡한 셀 값은 보류한다.
- 실제 재고는 영업 마감 후 센 수량을 기준점으로 유지한다. 이전 판매 수정은 차이를 다시 산출하되 실측 수량을 바꾸지 않는다. 같은 재료·날짜에 실측이 여러 개면 순서를 임의로 정하지 않고 오류를 알린다.
- 중간 계산 정밀도를 유지하고 금액은 화면에서 원 단위, 비율은 소수점 한 자리로 표시한다. 재료 잔량은 소수점 두 자리로 표시한다. 표시용 반올림으로 저장값을 바꾸지 않는다.
- 저장은 같은 기기·브라우저·주소 안에서 유지한다. 오래된 자료 버전으로 저장하려 하면 보류하고 새로 불러오도록 안내한다.
